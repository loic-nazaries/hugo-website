# AGENTS.md

Context for AI coding assistants working in this repo. Read this before exploring
the tree or making changes — it saves you from re-discovering the same structure
every session.

## What this repo is

Personal portfolio/blog website for Loïc Nazaries (data scientist), built with
**Hugo** (static site generator) using the **somrat** theme (vendored under
`themes/somrat/`, do not edit unless intentionally patching the theme).

Bilingual site: French (default) and English, via Hugo's multilingual config —
NOT two separate sites.

## Repo structure

```text
config/_default/       Hugo config (hugo.toml = main config, menus.fr.toml / menus.en.toml)
content/
  french/               FR content tree (default language, contentDir)
  english/              EN content tree (mirrors french/ 1:1, same filenames)
    blog/               Blog posts (.md, one per post)
    portfolio/           Portfolio project pages (.md, one per project)
    about.md, cv.md, contact.md, service.md, banner.md, etc.  Top-level pages
layouts/                Site-level template overrides (404.html, index.html) — only 2 files
themes/somrat/          Vendored Hugo theme — layouts, static assets (JS/CSS libs), do not touch casually
static/                 Site-wide static assets (images etc.)
assets/, resources/     Hugo pipeline assets / generated resource cache
public/                 Built site output — generated by `hugo`, NOT committed (gitignored), deployed by CI
.githooks/pre-push       Local git hook: runs `hugo --gc --minify` before push to catch build errors early
.github/workflows/hugo.yaml  CI: builds with Hugo (extended) + Dart Sass + Node, deploys to GitHub Pages on push to main
graphify-out/           Graphify-generated knowledge graph of this repo (GRAPH_REPORT.md, graph.json, graph.html) — use this to understand structure/relationships before deep manual exploration
netlify.toml            Legacy/alternate deploy config (Netlify) — actual deploy path is GitHub Actions + GitHub Pages, per README
```

## Key facts / gotchas

- **Content is duplicated per language.** `content/french/X.md` and
  `content/english/X.md` are separate files with the same relative path/filename.
  When editing content, check whether the change needs mirroring in both
  languages — don't assume one edit covers the site.
- **`public/` is NOT the source of truth and is NOT committed.**
  `.gitignore` excludes it. CI (`.github/workflows/hugo.yaml`) builds it fresh
  from `content/` + `config/` + `themes/` on every push to `main`, then
  deploys it to GitHub Pages. The pre-push hook only runs a local build as a
  sanity check — it never commits `public/`. Never hand-edit `public/` — it
  will be overwritten on next build.
- **Deploy pipeline:** GitHub Actions only (Hugo extended 0.160.x, Dart Sass,
  Node). Netlify config file exists but is not the active deploy path.
- **Pre-push hook:** run `git config core.hooksPath .githooks` once after
  cloning. It runs `hugo --gc --minify` locally before every push — a broken
  build blocks the push, catching errors before CI does.
- **Theme is vendored, not a submodule.** `themes/somrat/` is a full copy of
  the theme in-tree (includes its own `graphify-out/` cache from a prior run —
  ignore that, it's noise, not part of this site's own knowledge graph).
- **`.venv/`, `.mypy_cache/`** exist at repo root — there is some Python
  tooling used alongside the site (likely for the `graphify-out/query_*.py`
  scripts), not part of the Hugo build itself.
- Config defaults to **French** as primary language
  (`defaultContentLanguage = "fr"`, subdir mode). English is secondary.

## Before making changes

1. Check `graphify-out/GRAPH_REPORT.md` for a structural overview if the task
   touches multiple files or unclear relationships — it's already generated,
   no need to re-derive it manually.
2. Content edits: locate the matching page in **both** `content/french/` and
   `content/english/` unless the user explicitly wants a one-language change.
3. Theme/layout edits: prefer `layouts/` (site-level override) over editing
   `themes/somrat/layouts/` directly, unless patching the vendored theme itself
   is the explicit intent.
4. After any content/layout change, a local `hugo` build (or letting the
   pre-push hook run) is the fastest way to verify nothing broke, before
   relying on CI.
